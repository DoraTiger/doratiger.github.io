前言

IT-Tools 提供编码转换、文本处理和开发辅助工具，本身没有需要迁移的服务端用户系统。原来的实例放在 iStoreOS 上，这次将它迁到 TrueNAS，与 NPM 放在同一 Docker 网络，再用 Authentik 限制网页入口。

这里的统一认证不会在 IT-Tools 中创建账号。登录身份由 Authentik 管理，认证通过后直接打开工具页。

一、部署结构

浏览器 → tools.example.com → NPM → IT-Tools:80
                              ↕ 认证子请求
                       TrueNAS Proxy Outpost
                              ↕
                        云端 Authentik

业务请求留在 NAS，前哨负责检查会话和应用访问资格。本次使用 Authentik 与 Proxy Outpost 2026.8.5，IT-Tools 沿用迁移前的镜像内容，以摘要固定版本，没有同时升级工具站。

NPM 与前哨的基本关系见 统一认证实践（4）Authentik 接入 qBittorrent 与 NPM 统一认证。IT-Tools 不需要额外转发后端密码，因此配置比带本地登录的应用简单。

二、TrueNAS 自定义应用

2.1 镜像与网络

先在原主机记录镜像名称和 RepoDigest，再在 TrueNAS 拉取同一多架构镜像摘要。两台机器架构不同，可能使用不同平台层，不能直接比较容器镜像 ID 判断版本是否相同。

在 TrueNAS“应用 → 自定义应用”选择 YAML 安装。下面是可替换的最小示例；npm_backend 表示现有 NPM 的 Docker 网络，可在 TrueNAS 宿主机用 docker inspect NPM容器名 --format '{{json .NetworkSettings.Networks}}' 查看 NPM 加入的网络，再替换示例中的外部网络名：

services:
  it-tools:
    image: corentinth/it-tools@sha256:8b8128748339583ca951af03dfe02a9a4d7363f61a216226fc28030731a5a61f

networks:
  npm_backend:
    external: true
    name: npm_backend

此示例不发布宿主机端口。NPM 通过 it-tools-web:80 访问，容器地址变化时由 Docker DNS 解析。该网络必须已经存在，且 NPM 本身也在网络中。

2.2 持久数据与迁移

IT-Tools 是静态网页工具集，本次没有服务端用户数据库需要迁移，也没有复制原容器中无关的整目录挂载。浏览器本地保存的偏好仍属于原浏览器、原站点来源，改域名后不能假设自动出现。

启动新实例后先验证 HTTP 页面，再配置认证。迁移完成后停止旧容器，避免旧入口继续提供未经认证的相同工具。原定义可以保留用于回退。

三、Authentik 对象配置

3.1 访问组

进入“目录 → 组 → 创建”，名称填写 truenas-it-tools-users，不启用超级用户权限。保存后加入允许使用工具站的用户。

3.2 Proxy Provider

进入“应用程序 → 提供者 → 创建”，选择 Proxy Provider：

字段 配置
Name doratiger-truenas-it-tools
Authentication flow doratiger-authentication
Authorization flow doratiger-provider-authorization-implicit-consent
Invalidation flow doratiger-provider-invalidation
Mode Forward auth (single application)
External host https://tools.example.com
Unauthenticated paths 留空
HTTP Basic 转发 关闭

保存 Provider。后端工具站地址由 NPM 配置，External host 填浏览器入口。

3.3 应用与前哨

在“应用程序 → 应用程序”选择 with existing provider，名称填 TrueNAS · IT-Tools，Slug 填 truenas-it-tools，绑定上面的 Provider，Launch URL 填工具站 HTTPS 地址。

保存后打开应用的策略／组／用户绑定，增加 truenas-it-tools-users，Order 为 0，启用，Negate 关闭。

编辑 TrueNAS 上已有的 Proxy Outpost，在应用列表加入 IT-Tools，保留其他应用并保存。等待前哨接收配置，确认状态正常。单独创建应用但不关联前哨，不能完成 Forward Auth。

四、NPM HTTPS 与认证

4.1 Proxy Host

创建 Proxy Host，Domain Names 填 tools.example.com，Scheme 为 http，上游填 it-tools-web，端口 80。SSL 选择覆盖域名的证书并启用 Force SSL。

域名应解析到 NPM 入口。HTTPS 连通、Docker DNS 可解析和 Authentik 授权分别检查，不把证书错误当作账号问题。

port_in_redirect off;
set $ak_http_host $host;

location /outpost.goauthentik.io {
    proxy_pass http://authentik-outpost:9000;
    proxy_set_header Host $ak_http_host;
    proxy_set_header X-Original-URL $scheme://$ak_http_host$request_uri;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For $remote_addr;
    proxy_pass_request_body off;
    proxy_set_header Content-Length "";
}

location @goauthentik_proxy_signin {
    internal;
    add_header Set-Cookie $auth_cookie;
    return 302 /outpost.goauthentik.io/start?rd=$scheme://$ak_http_host$request_uri;
}

此例外部端口为标准 HTTPS 443。非标准端口应按官方模板调整外部 Host，避免回调丢失端口。Nginx 模板

4.3 根路径保护

在 Custom Locations 创建 /，上游同样填写 http、it-tools-web、80。打开该行齿轮，添加：

nginx

auth_request /outpost.goauthentik.io/auth/nginx;
error_page 401 = @goauthentik_proxy_signin;
auth_request_set $auth_cookie $upstream_http_set_cookie;
add_header Set-Cookie $auth_cookie;

保存后检查 NPM 配置是否有效。不要直接修改容器内自动生成的 host 文件，后续保存界面配置会覆盖它。

五、验证与维护

用无痕窗口打开工具站，预期先进入 DoraTiger Auth；组内用户登录后回到工具页。本次已确认工具页面正常打开。还应选择一个简单工具完成输入和输出检查，并用非成员身份确认应用拒绝访问。

IT-Tools 没有本地账号，因此没有旧账号绑定、自动注册或后端密码同步步骤。移除组成员会影响后续访问授权，但仍需考虑浏览器现有会话的有效期。

升级前记录当前镜像摘要，在 TrueNAS 自定义应用中更新镜像并重建。回退优先恢复旧镜像或旧容器，不修改云端共用登录流程。

六、配置问题与解答

6.1 容器之间是否必须经过宿主端口

Q：NPM 为什么直接填容器名称？

两个容器加入同一用户定义网络后，可以使用 Docker DNS 解析名称或别名。不发布宿主端口也能反代；代价是必须维护网络成员关系，重建应用时不能漏掉外部网络。

6.2 访问工具页是否等于获得独立工作空间

Q：每个 Authentik 用户会有独立的 IT-Tools 账号吗？

不会。认证层控制谁能访问静态站点，工具站并没有因此增加服务端用户系统。浏览器中的输入和偏好不等于统一身份中心管理的数据。
