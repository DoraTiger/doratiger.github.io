前言

装好 Authentik 就能用默认流程登录。想把注册改为仅限邀请，或者让用户在密码和 Passkey 之间选择，就需要知道每个阶段何时执行。这次索性把日常流程重新配置了一遍，逐项测试，再删除已经被替代的默认对象。

上一篇 统一认证实践（1）Authentik 基本概念、默认配置与部署 介绍了基本概念和部署。这篇继续使用 2026.8.5，从本地登录、MFA、邀请注册开始，接着配置找回密码、个人资料和应用授权。对象使用 doratiger- 前缀，域名统一用 auth.example.com 举例。

邮箱验证和密码恢复依赖可用的 SMTP。本文说明邮件阶段在流程中的职责；实际测试注册和找回密码前，需要完成 SMTP 配置并确认能够发信。

一、配置对象与依赖关系

1.1 流程与阶段创建

以下操作都在管理员界面完成。先区分几个创建入口：

对象 后台位置 创建后如何使用
流程 Flow 流程和阶段 → 流程 → 创建 添加阶段绑定，再由品牌、认证器设置或提供者选择该流程
阶段 Stage 流程和阶段 → 阶段 → 创建 选择阶段类型；也可在流程内直接创建并绑定
输入 Prompt 流程和阶段 → 输入 → 创建 在 Prompt Stage 的 Fields 中选中它
策略 Policy 自定义 → 策略 → 创建 选择策略类型，再绑定到目标或选入表单的 Validation Policies
事件 Event 事件 → 日志 系统执行操作时自动记录，用于核对结果，不需要为每个流程手工新建事件

创建流程时，Name、Slug 和 Title 是三个字段。Name 用于后台识别，可以写“DoraTiger 本地密码登录”；Slug 填 doratiger-authentication，用于 URL；Title 是用户打开流程时看到的标题，例如“登录 DoraTiger”。阶段、策略和输入表中的 doratiger-... 则填到各自的 Name，不是让所有对象都填写 Slug。

图为 Authentik 官方文档中的创建表单，用于对照字段位置。官方配图与本文实例的版本、语言和外观可能不同，实际填写值以下文为准。

以本地密码登录为例，创建流程后点击它的名称，进入“阶段绑定（Stage Bindings）”，点击“创建或绑定（Create or bind）”。首次添加时选“创建并绑定新阶段（Bind New Stage）”，选择阶段类型、填写名称与专用字段，再设置绑定顺序并保存。复用已经存在的阶段时，选“绑定已有阶段（Existing Stage）”，搜索对应名称，不要再创建一份。保存后回到列表，确认阶段名称、类型和顺序。阶段绑定操作

只有 Prompt Stage 需要另外准备“输入”。Identification、Password、TOTP Setup 等阶段自带交互界面，不需要自己再造一个用户名框或二维码页。

1.2 阶段绑定

除下文另有说明，阶段绑定使用：

字段 设置
Order 按各流程表格填写
Evaluate on plan 关闭
Re-evaluate policies 开启
Invalid response action Retry
额外策略绑定 没有明确需要时不添加

输入阶段中的 Validation Policies 是提交后验证；流程或阶段的策略绑定则决定是否执行。密码强度要放到前者。把它绑到阶段入口，可能在用户还没输入密码时就评估了。

还有三种看似相近的“策略关联”，操作位置不同：

目的 操作位置 本文例子
提交表单后检查填写内容 编辑 Prompt Stage → Validation Policies 密码强度、邀请邮箱、个人资料修改权限
决定整个流程能否进入 流程详情 → 策略／组／用户绑定 需要额外限制访问的流程
决定流程中的某一步是否执行 流程详情 → 阶段绑定 → 展开对应行 → 创建或绑定策略 默认登录中跳过部分阶段的条件策略

后两种方式选择已有策略后，还要保存策略绑定；第一种是在阶段表单中选择策略并保存阶段。本文的三个表单校验策略使用第一种方式，不额外绑定到流程入口。已有阶段的复用也只复用阶段内容，各流程中的绑定顺序和条件仍各自设置。策略绑定操作

1.3 密码策略

进入“自定义 → 策略”，点击创建，类型选择“密码策略（Password Policy）”，Name 填 doratiger-password-policy。它负责校验新密码的强度。本次使用以下参数：

字段 值
Password field password
Check static rules 开启
Minimum length 12
小写字母最少数量 2
数字最少数量 2
大写字母、符号最少数量 0
Check zxcvbn 开启，阈值 2
Check Have I Been Pwned 开启，允许泄露次数 0

填写后保存。此时只是创建了策略对象，还没有让任何表单使用它。配置注册或改密表单时，需要编辑对应 Prompt Stage，在 Validation Policies 中选中 doratiger-password-policy。Password field 的 password 对应输入对象的 Field key，不能填输入的 Name。

泄露密码检查需要服务端出站网络，网络故障应查看策略和请求日志，不能把它当作纯本地长度校验。本篇记录的是实际采用的参数，不代表所有站点都应使用相同强度。

后面的注册、找回密码和登录后改密，都引用这一条策略；日常登录的 Password Stage 验证已有密码，不负责给新密码打分。

二、本地密码登录

在“流程和阶段 → 流程”创建本地密码登录流程：

字段 填写内容
Name DoraTiger 本地密码登录
Slug doratiger-authentication
Title 登录 DoraTiger
Designation Authentication（认证）
Authentication requirement None／No requirement（无身份前提）

这里允许未登录用户进入，验证身份由流程内的阶段完成。保存后进入该流程的“阶段绑定”，按下面的顺序创建三个阶段：

顺序 阶段 类型与设置
10 doratiger-login-identification Identification；用户字段选择 Username、Email；Password stage 留空；注册、恢复、无密码入口暂时留空
20 doratiger-login-password Password；只选“用户数据库＋标准密码”后端
100 doratiger-login-session User Login；Session duration、Remember me offset 均为 seconds=0；不终止其他会话
  1. 创建并绑定“用户识别（Identification）”阶段，Name 填 doratiger-login-identification。User fields 选 Username、Email；Sources 暂时不选；Password stage 留空，表示密码校验使用单独阶段。绑定 Order 填 10。
  2. 再创建并绑定“密码（Password）”阶段，Name 填 doratiger-login-password。Backends 只选用户数据库的标准密码后端，绑定 Order 填 20。
  3. 创建并绑定“用户登录（User Login）”阶段，Name 填 doratiger-login-session。按表格设置会话参数，绑定 Order 填 100。
  4. 返回阶段绑定列表，确认依次为用户识别、密码校验、建立会话。这里的阶段名称用于后台检索，不是登录页上的提示文案。

图源为 Authentik 官方流程文档。这是基础密码登录的关系示意图，尚未包含 MFA。

识别阶段先找到 pending_user，密码阶段证明用户掌握该账号的密码，最后的 User Login 才建立登录会话。识别账号本身不等于认证成功。

Password Stage 中看到的四个后端分别服务于标准本地密码、应用程序密码、LDAP 密码和 Kerberos 密码。目前没有用后两种目录认证，普通网页登录也没有要求接受应用程序密码，因此只启用标准密码后端。

识别阶段的 Pretend user exists 已开启，Show matched user 在当前密码登录入口开启。后者会显示匹配用户信息，因此不能宣称这个登录入口完全隐藏账号存在性。找回密码入口会单独关闭它。

三、多因素认证与凭据管理

3.1 TOTP 设置

TOTP 设置用于给已登录账号绑定动态验证码应用。按下面的顺序创建：

  1. 在“流程和阶段 → 流程”创建流程，Name 填“DoraTiger TOTP 设置”，Slug 填 doratiger-totp-setup，Title 填“设置动态验证码”；Designation 选 Stage configuration（阶段配置），Authentication requirement 选 Require authenticated（要求已登录）。
  2. 打开新流程的阶段绑定，创建并绑定“TOTP 认证器设置（TOTP Authenticator Setup）”阶段，Name 填 doratiger-mfa-totp-setup，Digits 填 6，绑定 Order 填 0。
  3. 在“流程和阶段 → 阶段”找到刚创建的阶段，编辑 Configure flow，选择“DoraTiger TOTP 设置”，保存。这个引用让用户凭据页能找到设置入口。
  4. 用测试账号登录，进入用户设置的“凭据 → MFA 设备”，打开 TOTP 设置，扫描二维码并输入一次验证码。完成后确认凭据列表中出现设备。登录流程绑定 MFA 验证阶段后，再退出并测试登录验证。

3.2 备用恢复码

备用恢复码通过“静态认证器设置（Static Authenticator Setup）”阶段生成：

  1. 新建流程，Name 填“DoraTiger 备用恢复码设置”，Slug 填 doratiger-recovery-codes-setup，Title 填“生成备用恢复码”；Designation 选 Stage configuration，Authentication requirement 选 Require authenticated。
  2. 在该流程的阶段绑定中创建 Static Authenticator Setup 阶段，Name 填 doratiger-mfa-recovery-setup；Token count 填 10，Token length 填 12；绑定 Order 填 10。
  3. 编辑该阶段，把 Configure flow 选为“DoraTiger 备用恢复码设置”，保存。
  4. 从用户凭据页面进入此设置流程，生成并保存恢复码。MFA 验证阶段配置好后，用其中一个恢复码测试登录，并确认同一码不能再次使用。

每个恢复码使用后失效。用户生成后应自行妥善保存；它用于第二因素应急，不是密码找回邮件中的令牌。

3.3 WebAuthn 设置

在“流程和阶段 → 流程”新建“DoraTiger WebAuthn 设置”，Slug 填 doratiger-webauthn-setup，Title 填“添加安全密钥或 Passkey”，Designation 选 Stage configuration，Authentication requirement 选 Require authenticated。

打开阶段绑定，创建“WebAuthn 认证器设置（WebAuthn Authenticator Setup）”阶段，Name 填 doratiger-mfa-webauthn-setup，绑定 Order 填 10。阶段参数如下：

字段 值
User verification Required
Resident key requirement Preferred
Configure flow doratiger-webauthn-setup

保存阶段后，从用户设置的“凭据 → MFA 设备”进入 WebAuthn 设置，按浏览器提示选择设备并完成注册。Configure flow 选择的是刚创建的设置流程，不是密码登录流程。

浏览器必须通过有效 HTTPS 访问正确域名。用户验证由认证器提供，例如设备 PIN 或生物识别。

当前配置允许不同认证器能力；要使用后面的无用户名 Passkey 登录，应注册支持可发现凭据的 Passkey。若希望强制所有新凭据都可发现，可选择 Required，但那是不同于本次实测设置的取舍。

3.4 MFA 登录

打开“流程和阶段 → 流程 → DoraTiger 本地密码登录 → 阶段绑定”，创建并绑定“认证器验证（Authenticator Validation）”阶段。Name 填 doratiger-login-mfa，它负责登录时验证已有的第二因素。阶段参数如下：

字段 值
Device classes Static、TOTP、WebAuthn
Not configured action Configure
Configuration stages 仅选择 doratiger-mfa-totp-setup

绑定到 doratiger-authentication 的顺序 30，放在密码之后、建立会话之前。已有设备时验证相应设备；没有兼容设备时注入 TOTP 设置步骤。Skip 会允许跳过 MFA，Deny 会拒绝没有设备的用户，这两种行为均不符合当前首次登录引导的目标。认证器验证阶段文档

保存后，阶段列表应为 Order 10 用户识别、20 密码、30 MFA、100 用户登录。用已绑定 TOTP 的账号验证一次，再用未绑定验证器的测试账号确认会进入 TOTP 设置。这里选择的 Configuration stages 是设置阶段 doratiger-mfa-totp-setup，不是设置流程的 Slug。

3.5 独立 Passkey 登录

在流程列表新建“DoraTiger Passkey 登录”，Slug 填 doratiger-passkey-authentication，Title 填“使用 Passkey 登录”，Designation 选 Authentication，Authentication requirement 选 None／No requirement。

进入该流程的阶段绑定，先创建认证器验证阶段，再绑定已有的用户登录阶段：

顺序 阶段 配置
10 doratiger-passkey-validation Authenticator Validation；仅 WebAuthn；User verification 为 Required；未配置时 Deny；Configuration stages 留空
100 doratiger-login-session 复用会话建立阶段

第一行选择“创建并绑定新阶段”，类型为 Authenticator Validation，Name 填 doratiger-passkey-validation，按表格仅允许 WebAuthn。第二行选择“绑定已有阶段”，搜索 doratiger-login-session，Order 填 100。此流程不添加 Identification 或 Password 阶段。

在 doratiger-login-identification 的 Passwordless flow 中选择它，登录页才会出现无密码入口。

两条登录路径现在分别是：

四、邀请注册与邮箱验证

4.1 注册输入

进入“流程和阶段 → 输入”，逐个点击创建。每个输入都有后台 Name、数据字段键 Field key 和用户看到的 Label。以邮箱为例，Name 填 doratiger-enrollment-email，Field key 填 email，Label 填“邮箱”；Type 选 Email，Required 开启，Order 填 30，初始值留空。

按相同方式创建下面五项，Required 均开启，初始值及初始值表达式均不设置：

名称 Field key 类型 顺序
doratiger-enrollment-username username Username 10
doratiger-enrollment-name name Text 20
doratiger-enrollment-email email Email 30
doratiger-enrollment-password password Password 40
doratiger-enrollment-password-repeat password_repeat Password 50

标签分别填写用户名、显示名称、邮箱、密码、确认密码。两个 Password 输入在同一阶段，原生会检查它们一致，无需额外写比较策略。

plan = request.http_request.session.get(SESSION_KEY_PLAN)
if not plan:
    ak_message("注册会话已失效，请联系管理员重新获取邀请。")
    return False

invitation = plan.context.get("invitation")
if not plan.context.get("invitation_in_effect") or invitation is None:
    ak_message("请通过有效邀请链接注册。")
    return False

expected = (invitation.fixed_data.get("email") or "").strip()
submitted = (
    request.context.get("prompt_data", {}).get("email") or ""
).strip()

if not expected:
    ak_message("邀请未指定邮箱，请联系管理员重新创建邀请。")
    return False
if submitted.casefold() != expected.casefold():
    ak_message("请使用邀请指定的邮箱注册。")

图为官方的改密流程示例，右侧显示下一阶段及执行历史，不是本文实例的测试截图。检查器会真实执行流程，User Write 仍会写入数据；上下文还可能显示密码，应使用测试账号，不公开未经脱敏的上下文截图。

再进入“事件 → 日志”，按测试时间和测试用户查找登录、失败或其他相关记录，打开详情核对事件动作、用户和上下文。事件由操作产生，不需要额外建一个“登录事件”并绑定到流程。日志中有错误时，再结合检查器判断停在哪个阶段；不是每一个表单步骤都会对应一条独立事件。

通知规则和通知传输用于把选定事件发给接收者，与流程的 Stage Bindings 是不同配置。本篇验证流程执行结果时不需要新增邮件通知规则，也不要直接删除仍在工作的通知配置。

8.2 功能验证记录

按功能逐项检查，避免只看登录首页能否打开：

检查 本次结果
本地密码登录、TOTP、恢复码、WebAuthn 实际使用测试通过
独立 Passkey 登录 已配置并完成登录测试
邀请注册、指定邮箱验证、MFA 配置 实际注册测试通过
找回密码后新密码登录，继续要求 MFA 实际测试通过

主动改密 临时账号测试：弱密码及不一致密码被拒绝，新密码有效、旧密码失效

服务端验证使用临时账号和事务回滚，没有修改管理员密码，也没有留下测试账号。登录、找回密码以及通知需要的既有自建配置保持不变。

判断是否完成迁移，应看实际入口、绑定和策略引用，不能只统计流程数量或检查名称前缀。

九、配置问题与解答

9.1 登录流程未切换

Q：品牌已经选择自建认证流程，为什么浏览器仍显示默认登录页？

A： 检查当前域名匹配的 Brand，以及它的 Authentication flow。浏览器如果仍停在旧流程 URL，刷新只会继续访问旧流程，需要重新从站点首页进入。默认流程删除后，旧标签页也应从站点入口重新打开，无需重建同名默认流程。

9.2 Configure flow 的引用关系

Q：认证器设置阶段为什么又指回包含自己的流程，会不会递归执行？

A： 流程的阶段绑定决定进入流程后执行哪些步骤；阶段的 Configure flow 则决定用户在凭据页点击配置时打开哪个流程。两者用途不同，Configure flow 不是执行完阶段后再次跳转的指令。

9.3 凭据设置入口重复

Q：为什么 MFA 设备页面同时出现默认英文入口和自建入口？

A： 默认认证器设置阶段及其 Configure flow 仍然存在。新建自定义阶段不会自动替换旧对象，改名也不会合并入口。核对引用、测试自建入口后，再按清理顺序删除不再使用的默认设置阶段和流程。

9.4 Passkey 登录入口缺失

Q：WebAuthn 凭据已经注册，为什么登录页没有 Passkey 入口？

A： WebAuthn 设置流程负责注册凭据，独立无密码流程负责验证凭据并建立会话。还需要在当前登录识别阶段的 Passwordless flow 中选择 doratiger-passkey-authentication，登录页才有对应入口。

9.5 邀请注册提交后停留在表单

Q：输入用户名和密码后点击“继续”，为什么没有进入邮箱验证或 MFA？

A： 本次遇到的问题来自邀请邮箱策略读取上下文的方式。2026.8.5 的 Prompt 验证策略可以直接读取 prompt_data，但没有同样直接提供 flow_plan。改为通过 SESSION_KEY_PLAN 从当前 HTTP 会话取得执行计划，再读取邀请数据后，测试通过。正文给出的是修正后的策略；策略测试器没有真实邀请会话，仍需使用邀请链接验证。

9.6 邀请管理入口不可见

Q：创建邀请阶段后，为什么后台没有“邀请”菜单，或手工打开地址提示 URL 不存在？

A： 创建 Invitation Stage 后刷新后台，再进入“目录 → 邀请”。本版本实际路由是 /if/admin/#/flow/stages/invitations，不是 /if/admin/#/directory/invitations。

9.7 注册中断后的邀请与用户状态

Q：没有完成注册，为什么邀请已经不能使用，或者邮箱已有用户记录？

A： 当前版本的单次邀请在通过邀请阶段时就可能被消耗，不会一直保留到整个注册成功。用户写入阶段又在邮箱验证之前执行，因此中断后可能留下未激活用户。重试前应检查邀请和该邮箱的用户记录，再决定如何恢复，不要反复创建邀请或重复账号。

9.8 默认策略的引用检查

Q：普通策略绑定列表没有引用，是否就可以删除默认策略？

A： 还需要检查 Prompt Stage 的 Validation Policies。密码强度和用户资料权限策略可能直接被输入阶段引用，不一定出现在普通 Policy Binding 列表中。应先替换这些引用，再删除旧策略。

9.9 未绑定阶段的清理

Q：对象都使用 doratiger- 前缀，是否就表示清理完成？

A： 命名前缀不能说明对象是否仍在使用。本次排障曾留下未绑定的 doratiger-invitation-finish 阶段，它不参与执行，新部署无需创建。应结合入口、阶段绑定和策略引用检查残留对象。
