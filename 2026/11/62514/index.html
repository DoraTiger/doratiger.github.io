前言

统一账号不一定要在每个软件前面加一层网页登录。对于制品仓库，我更希望用户直接使用身份中心的账号，仓库权限仍在 Nexus 内管理。本次采用 Nexus 原生 LDAP 接入 Authentik，保留原来的本地 admin 作为备用入口。

实机运行 Nexus Repository Community 3.82.0-08、Authentik 2026.8.5，LDAP Outpost 与 Authentik 使用同一版本。镜像标签是 latest，正文版本来自运行服务，不能用标签判断实际版本。

一、认证结构

text
1
2
3
4
5
浏览器／仓库客户端 → NPM HTTPS → Nexus
                                  ↓ LDAPS
                          TrueNAS LDAP Outpost
                                  ↓ HTTPS
                           云端 Authentik

NPM 保持普通反向代理，不增加 Forward Auth。用户在 Nexus 登录框输入 Authentik 用户名和密码，不跳转身份中心；Nexus 通过 LDAP 查询用户、验证密码、读取组，再根据本地角色授予仓库权限。

OIDC 适合应用主动跳转身份中心完成登录，LDAP 适合应用原生验证统一用户名密码。两者是按服务能力选择的接入方式。本次 Nexus 只部署 LDAP，没有另加 OIDC 插件，也没有把仓库协议请求重定向到网页登录页。

本文域名、路径和账号使用示例。LDAP Base DN 使用 ou=nexus3,dc=ldap,dc=example,dc=com，内部服务名使用 ldap.example.internal，它由 Docker 网络解析，不需要公网 DNS。

二、Authentik 目录配置

2.1 用户组与查询账号

在“目录 → 组”创建 truenas-nexus3-users 和 truenas-nexus3-admins，均不启用 Authentik 超级管理员权限。普通成员加入 users 组；仓库管理员同时加入两组。组名带部署位置，避免以后另一台主机部署 Nexus 时混用授权。

在“目录 → 用户”创建 svc-example-nexus3-reader，类型选择 Service account，设置独立随机密码。该账号供 Nexus 查询目录，不复用人的登录密码，也不授予超级管理员权限。

2.2 LDAP 绑定流程

LDAP 不能执行网页重定向或 Passkey 交互。进入“流程和阶段”，新建身份认证流程，名称 DoraTiger LDAP authentication，Slug doratiger-ldap-authentication，Designation 为 Authentication。

创建 Password 阶段 doratiger-ldap-password，启用用户数据库标准密码与应用程序密码后端。再创建 Identification 阶段 doratiger-ldap-identification，用户字段选择 username，Password stage 引用刚建的密码阶段。最后创建 User Login 阶段 doratiger-ldap-login。

进入流程的“阶段绑定”，按顺序添加识别阶段（Order 10）和用户登录阶段（Order 30）。密码阶段由识别阶段调用，不重复绑定。已有这套流程时复用即可，原网页登录和 MFA 流程不修改。

2.3 Provider、应用和搜索权限

在“应用程序 → 提供者”创建 LDAP 类型：

字段 配置
Name doratiger-truenas-nexus3-ldap
Bind flow／Authorization flow doratiger-ldap-authentication
Invalidation flow 现有 doratiger-provider-invalidation
Base DN ou=nexus3,dc=ldap,dc=example,dc=com
Bind mode / Search mode Direct / Direct
TLS server name ldap.example.internal
Certificate SAN 包含上述名称的服务证书
MFA support 关闭

证书在“系统 → 证书”中管理；导入服务端证书及私钥，客户端仅配置相应信任证书。同一前哨承载多个 Provider 时，每个 Provider 使用不同 Base DN。本次使用一年期自签证书并明确建立客户端信任，续期必须同步维护。

在应用程序中选择 with existing provider，名称 TrueNAS · Nexus3 LDAP，Slug truenas-nexus3-ldap，选择刚创建的 Provider。策略引擎模式设为 ANY，在应用详情的“策略／组／用户绑定”分别添加 users 组和查询账号，Order 0、1，均启用、不取反。

打开“目录 → 角色”，创建 RBAC 角色 doratiger-nexus3-ldap-search，在角色的 Users 页添加查询账号。回到刚建的 LDAP Provider，打开 Permissions → Assign role object permission，选中这个角色并勾选 Search full LDAP directory，保存。应用绑定决定能否使用应用，搜索权限决定能否执行完整目录查询，两处都要配置。

四、Nexus LDAP 配置

4.1 备份与证书信任

使用原本地 admin 登录 Nexus。在改动前备份数据目录，并保存当前 LDAP、Realms、Users、Roles 配置。本文不修改已有仓库和制品，也不把 admin 改成 LDAP 用户。

进入“Administration → Security → SSL Certificates”，导入 LDAP 服务端的信任证书。连接使用自签证书时这一步不能省略，否则会出现 TLS 验证失败。连接名称必须匹配证书 SAN；不要改用容器 IP 后关闭证书校验。

4.2 连接参数

进入“Security → LDAP → Create connection”，填写：

字段 配置
Name DoraTiger Auth LDAP
Protocol / Host / Port LDAPS / ldap.example.internal / 6636
Use Nexus Repository truststore 开启
Search base ou=nexus3,dc=ldap,dc=example,dc=com
Authentication method Simple
Username / Bind DN cn=svc-example-nexus3-reader,ou=users,ou=nexus3,dc=ldap,dc=example,dc=com
Password 查询账号独立密码
Connection timeout 30 秒

保存或进入下一步前执行连接测试。TLS、查询账号密码、Base DN 都正确后再配置用户映射。

4.3 用户属性

字段 配置
User relative DN ou=users
User subtree 关闭
Object class user
User filter (memberOf=cn=truenas-nexus3-users,ou=groups,ou=nexus3,dc=ldap,dc=example,dc=com)
User ID attribute cn
Real name attribute cn
Email attribute mail
Password attribute 留空，使用绑定验证

Authentik 的 cn 是用户名，uid 是不透明的唯一标识。这里用 cn 作为 Nexus 登录用户名。过滤条件只返回允许使用此实例的人员，不能因为查询账号有完整目录权限就省略过滤。

4.4 组属性

启用 LDAP groups as roles，组类型选 Static：

字段 配置
Group relative DN ou=groups
Group subtree 关闭
Group object class groupOfNames
Group ID attribute cn
Group member attribute member
Group member format cn=${username},ou=users,ou=nexus3,dc=ldap,dc=example,dc=com

保存后测试用户映射，选择已有 Authentik 用户，确认能读取 users 和 admins 组。不要把其他 LDAP 教程里的 uniqueMember 直接套过来，本次目录实际使用 member。

五、角色与认证域

5.1 本地角色映射

在“Security → Roles”创建 Nexus role，角色 ID 必须匹配 LDAP 组名称，显示名称可以另填：

Role ID 显示名称 权限／包含角色
truenas-nexus3-users DoraTiger Nexus3 readers nx-repository-view-*-*-browse、nx-repository-view-*-*-read
truenas-nexus3-admins DoraTiger Nexus3 administrators 包含内置 nx-admin 角色

普通组当前只读，不能据此认为已有上传权限。需要发布制品时，再按目标仓库创建最小写入角色。管理员同时属于两个组，完整管理能力由管理员组授予。

5.2 启用 LDAP Realm

进入“Security → Realms”，保留已启用的 NexusAuthenticatingRealm，增加 LdapRealm 并保存。保留本地认证域是为了让原 admin 继续可用，不应为启用 LDAP 把原认证域移走。

退出后用无痕窗口输入 Authentik 用户名和密码。我用目录账号登录后能看到原仓库和管理设置，本地 admin 也能登录。要验证制品权限，还需要用普通账号在相应格式的仓库中实际下载，并检查它能否向受限仓库上传。

六、维护与配置问题

6.1 角色列表为空

Q：接口查到用户，但 roles 是空数组，是否没有获得 LDAP 组？

本次检查 /service/rest/v1/security/users?source=LDAP&userId=USER 时，roles 为空，但 externalRoles 已返回目录组。两个字段用途不同。应同时核对外部组、本地同名角色和实际操作权限，不因单个字段为空重复修改 LDAP 过滤条件。

6.2 本地前哨与云端依赖

Q：前哨就在 TrueNAS，密码验证是否完全在本地完成？

当前 Bind/Search 均为 Direct，前哨仍访问云端 Authentik。本地前哨解决协议和网络接入问题，不提供独立的离线密码库。云端不可达会影响新的 LDAP 认证，因此保留本地管理入口。尚未进行分段延迟测试，也没有启用缓存来替代直接验证。

6.3 MFA 与密码

Q：LDAP 登录是否会弹出网页 MFA？

不会。本次专用绑定流程验证密码，Provider 的 MFA support 关闭。网页登录流程仍可使用 MFA，但那是另一条认证路径。只通过 Google 或 Microsoft 登录身份中心、没有设置可用本地密码的用户，需要先在 Authentik 设置密码，不能把第三方账号密码直接交给 Nexus。

6.4 撤销访问与回退

Q：从组里移除用户，是否会立即结束所有客户端会话？

不能这样推断。组和应用策略影响后续认证授权，已有会话、客户端缓存和已签发凭据还需在 Nexus 侧处理。停用用户时同时检查这些状态。

回退时用本地 admin 登录，恢复原 Realm 列表并停用 LDAP 连接；确认无依赖后再移除本次角色与 Authentik 对象。不要删除原仓库或整库恢复覆盖新上传的制品。前哨若还供 Jellyfin 使用，应保留服务，只移除 Nexus 专属 Provider。
